# UCNS agent instructions

- Treat UCNS as a geometry and mathematical-representation repository whose cross-domain role is geometric scale/representation transport, never semantic transfer.
- Read `CANON.md` before changing domain behavior.
- Placement test: if work constructs geometric carriers, motion, attachment, recursion, or transport across a declared scale/representation boundary, it may belong in UCNS.
- If work defines what the transported structure means in a domain, keep that meaning with the domain consumer or METAPAT authority.
- If work measures whether a claimed transformation preserves an observable, keep that measurement in EDCM; UCNS supplies only the represented geometry and its own mathematical evidence.
- Keep only code, tests, documents, and evidence that directly construct, represent, certify, falsify, or replay geometry/topology.
- Do not introduce lexical, NLP, dictionary, morphology, definition, semantic-graph, EDCM-measurement, PTCNA-state, generic evaluator/laboratory, or cross-stack adapter machinery into UCNS.
- Every Public Gonol glyph is a function position. Do not create letter/punctuation/digit/symbol subclasses as UCNS architecture.
- Do not infer Public Gonol function behavior from Unicode names or dictionary definitions.
- Preserve the exact 157-position Public Gonol arrangement and its digest as a historical/public function carrier; do not use it as the active admission gate or angular registry for arbitrary Unicode text.
- For active text geometry, use exact Unicode scalar identity with SPACE-relative scalar bearing and exact UTF-8 byte/bit anatomy; never normalize canonically equivalent scalar sequences.
- UCHC Unicode gonols use fixed 16-bit radius (b rad), 32-bit diameter and four-byte big-endian scalar representation (UTF-32BE, no inserted BOM). ASCII has three leading zero bytes. Bit width and geometric placement radius are separate quantities.
- Primitive text siblings share one exact radius. Do not use ordinal radius-halving as the active text placement law. Closed constructions retain interiors across scales; unresolved next-scale bearing/affixiation remains hmmm rather than being filled from historical candidates.
- Preserve the native Möbius distinction: 360° visible return; 720° complete local return.
- Geometry candidates remain candidates until their own declared falsifiers, replay, and ratification justify stronger standing.
- Preserve exact arithmetic where exactness is load-bearing; lossy renderings remain explicitly secondary.
- Use `hmmm` for unresolved geometric constraints. Never fill a missing geometric law with semantic machinery or implementation convenience.
- Every behavior-bearing source module owns skill-lib `MODULE_BUILD` and `CONTRACTS`; executable tests own resolving `CHECKS`.
- Before claiming test-backed status run the complete geometry suite through the outcome gate documented in README, `.venv/bin/python tools/verify_skill_lib_contracts.py .`, build, and Twine checks. Use the project interpreter populated by `uv sync --locked --extra test --extra build` for these checks.
